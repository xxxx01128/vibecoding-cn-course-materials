# 拿来说明 01：术语驱动的翻译一致性

> 关键决策：**先建术语表，再翻译，最后用脚本反向校验**。解决"同一术语几十种译法"的老大难问题。
> 结构：背景 → 原文/素材 → prompt → 产出 → 对比 → 复用方法。

---

## 一、要解决的问题

AI 辅助编程课程里，`Code Review`、`Vibe Coding`、`Context Engineering`、`MCP` 这些词出现频率极高。如果让 AI 逐篇独立翻译，同一个 `Code Review` 会随机变成"代码评审 / 代码审查 / 代码检视 / code review"——读者会以为是不同概念。这是机翻最典型的硬伤，也是 Rubric「术语统一」明确扣分的点。

## 二、原文 / 素材（输入）

以 `原文/13_how-to-review-code-effectively.md` 中的一组句子为例：

> **原文**：
> "Code review is the process by which a developer reviews code written by another developer... A good PR keeps the diff small."
>
> 全课程中 `Code Review` 出现数百次，`PR` / `Pull Request` 数十次，散布在 30 篇文档中。

## 三、Prompt（我用 AI 做的事）

**第一步：让 AI 生成术语表候选**

> 你是技术文档本地化专家。下面是一套 AI 编程课程的核心术语（给出英文列表）。请产出一份英中术语表 JSON，每条含 `en`、`zh`、`note`。要求：译法唯一、符合中文技术写作习惯、对易混淆词在 note 里写明"禁用哪些译法"。产品名保留英文。

**第二步：把术语表注入翻译 prompt（v3 节选）**

> 术语严格按 `glossary.json` 的 `zh` 字段译法。术语首次出现可括注英文（如"氛围编程（Vibe Coding）"），其后统一用中文译法。产品名（Claude Code、Codex、Warp、Cursor、Kubernetes、OWASP）保留英文。
> 速查：Code Review→代码评审；Vibe Coding→氛围编程；Context Engineering→上下文工程；MCP→模型上下文协议（MCP）。

**第三步：让 AI 写反向校验脚本**

> 写一个脚本，读取术语表，检测译文中是否出现被禁用的竞争译法（如"代码审查" vs 术语表"代码评审"），统计每处并输出报告。

## 四、产出

1. **`术语表/glossary.json`**：68 条术语，每条含 en / zh / note。例如：
   ```json
   {"en": "Code Review", "zh": "代码评审", "note": "全文统一，不用「代码审查」"},
   {"en": "Vibe Coding", "zh": "氛围编程", "note": "课程名核心词；不用「直觉编程」"},
   {"en": "Context Engineering", "zh": "上下文工程", "note": "与提示工程区分"}
   ```
2. **译文中的实际效果**（`译文/13_how-to-review-code-effectively.md`）：

   > **译文**："代码评审是开发者审阅另一位开发者所写代码的过程……一个好的 PR 会让改动保持很小。"
   > 全篇 `Code Review` 统一译为"代码评审"，首次出现写作"代码评审（Code Review）"。

3. **`pipeline/03_qa_check.py`**：自动扫描全部译文，统计竞争译法出现次数。

## 五、对比（用与不用术语表的差别）

| 维度 | 不用术语表（v1 直译） | 术语表驱动（v3 + 校验） |
|---|---|---|
| `Code Review` 译法 | 评审 / 审查 / 检视 / 保留英文，**4 种混用** | 全部"代码评审"，**1 种** |
| `Vibe Coding` | 氛围编程 / 直觉编程 / 共鸣编码 | 全部"氛围编程" |
| 产品名 | 出现"克劳德代码"等误译 | 全部保留 `Claude Code` |
| 发现问题的方式 | 人工通读，耗时且易漏 | 脚本秒级扫描，可复核 |
| 换一门课 | 术语全部重来 | 换 `glossary.json` 即可复用 |

**QA 报告实测**：术语不一致问题 **0 处**（见 `qa/qa_report.md` 汇总）。

## 六、怎么拿来用

1. 把 `术语表/glossary.json` 换成你所在领域的术语（字段结构不变）。
2. 把 `note` 里写清"禁用译法"，这是校验脚本检测竞争译法的依据。
3. 翻译 prompt 里引用术语表，并强调"首次括注、其后统一"。
4. 翻译后跑 `python pipeline/03_qa_check.py`，看"术语不一致"是否为 0。

> **一句话**：术语表不是词表，是**译法的法律**；先用 AI 立法，再让 AI 守法，最后用脚本执法。
