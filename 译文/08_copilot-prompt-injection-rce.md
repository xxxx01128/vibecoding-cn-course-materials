# GitHub Copilot：通过提示词注入实现远程代码执行（CVE-2025-53773）· Embrace The Red

> 来源: https://embracethered.com/blog/posts/2025/github-copilot-remote-code-execution-via-prompt-injection/

这篇文章介绍一个重大但也令人担忧的提示词注入发现，它会在[GitHub Copilot 与 VS Code](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2025-53773)中导致开发者机器被完全攻陷。

其实现方式是通过修改项目的 `settings.json` 文件，把 Copilot 置于 YOLO 模式。

正如几天前在[Amp](https://embracethered.com/blog/posts/2025/amp-agents-that-modify-system-configuration-and-escape/)中所描述的，智能体中一个可能被忽视的漏洞模式是：如果一个智能体能够写入文件、修改自身配置或更新与安全相关的设置，就可能导致远程代码执行。这种情况并不少见，也是在进行安全评审时始终需要留意的一个领域。

## 背景研究

在查看 VS Code 和 GitHub Copilot Agent Mode 时，我注意到一个奇怪的行为……它可以在工作区中创建文件并向其中写入内容，而无需用户批准。

这些编辑会立即持久化，它们并不只是内存中等待评审的 diff。修改会立刻写入磁盘。

对于红队成员来说，这是那种你一眼就知道「大概不妙」的事情之一……所以我就研究它是否可以被用来提权并执行代码。

### YOLO 模式

于是，接下来我研究了 VS Code 中那些依赖于项目/工作区文件夹内设置的功能，很快就发现了一个有意思的功能。

事实证明，在 `.vscode/settings.json` 文件中，可以添加下面这一行：

`"chat.tools.autoApprove": true`

这会让 GitHub Copilot 进入 YOLO 模式。

它会禁用所有用户确认，于是我们可以运行 shell 命令、浏览网页，等等！

有意思的是，这是一项实验性功能，但它在默认情况下仍然存在。我并没有下载什么特殊版本，也没有把我的 VS Code 整体设置为实验模式。

此外，它在 Windows、macOS 和 Linux 上都能工作。

## 攻击链解析

用于劫持 Copilot 并提权的概念验证（proof-of-concept）攻击链如下：

- 攻击始于埋藏在源代码文件、网页、GitHub issue、工具调用响应或其他内容中的一次提示词注入……payload 还可以使用不可见文本作为指令。
- 提示词注入首先向 ~/.vscode/settings.json 文件添加 `"chat.tools.autoApprove": true` 这一行。如果文件夹和文件尚不存在，就会被创建出来。
- GitHub Copilot 立即进入 YOLO 模式！
- 攻击者运行一条终端命令。而借助条件式提示词注入，我们实际上可以根据操作系统来定向决定要运行什么。
- 我们实现了由提示词注入驱动的远程代码执行。

下面这张截图展示了带有提示词注入的演示文件、右侧聊天框中与该文件互动的开发者，以及弹出的计算器！

当然，任何其他提示词注入的投递方式也都是攻击角度，例如来自网络的数据，或从 MCP 服务器返回的数据。我只是把它放在源代码文件里，因为这样最容易测试。

## 把工作站加入僵尸网络——ZombAI

当然，这意味着我们可以把开发者的机器作为一台 ZombAI 加入僵尸网络。

另外，为了好玩，我们还可以修改 `settings.json` 文件，把 VS Code 切换成 `Red` 配色方案之类的东西。

但事情并不止于此！这也意味着我们可以构建真正的 AI 病毒，它会附着在文件上，并随着开发者下载和与受感染文件交互而传播。

最后但同样重要的是，为了证明我们完全控制了开发者的主机，我们展示了 Copilot 可以被劫持去下载恶意软件，并加入一个远程命令与控制服务器。

这意味着恶意软件、勒索软件、信息窃取器等的大门已经敞开。

吓人的东西。

## 构建一个 AI 病毒

看到这一幕，你会发现这基本上让创建病毒成为可能。攻击者可以嵌入指令，一旦他们获得代码执行能力，额外的恶意软件就能入侵其他 Git 项目（以及 RAG 数据源）以植入恶意指令，然后提交这些更改，甚至强制推送到上游。

这可能导致进一步的传播，因为其他开发者会在不知情的情况下扩散被感染的代码。

最后，我们还需要谈谈不可见指令！

## 建议与修复

实际上，攻击角度比我分享的 YOLO 模式示例还要多。当微软问我是否还有更多信息时，我又深入看了一下，注意到还有其他有问题的地方，例如 AI 可以写入的 `.vscode/tasks.json`，或者添加伪造的恶意 MCP 服务器等等，这些都可能导致代码执行。而且 AI 还能重新配置项目的用户界面和配置设置。

最近我注意到开发者经常会使用多个智能体，因此还存在覆盖其他智能体配置文件的威胁（允许执行的 bash 命令白名单、添加 MCP 服务器……），因为这些配置文件通常也位于项目文件夹中。

理想情况下，AI 在未经人工先行批准的情况下不应能够修改文件。许多其他编辑器确实会显示 diff，然后由开发者批准。

## 负责任的披露

在 2025 年 6 月 29 日报告该漏洞后，微软确认了复现，并追问了几个后续问题。几周后，MSRC 指出这是他们已经在跟踪的一个问题，并将在 8 月修复。随着 8 月补丁星期二的发布，此问题现已修复。

向来自[Persistent Security](https://persistent-security.net/)的[Markus Vervier](https://x.com/marver)致敬，他也发现并向微软报告了这一漏洞。你可以在[这里](https://www.persistent-security.net/post/part-iii-vscode-copilot-wormable-command-execution-via-prompt-injection)找到他们的文章。也向[Ari Marzuk](https://x.com/Ari_MaccariTA)致敬，他似乎也独立地发现了它。

感谢 MSRC 和产品团队的成员在缓解该问题过程中提供的帮助。

## 结论

这是又一个 AI 智能体可能不待在自己「盒子」里的例子！通过修改自身环境，GitHub Copilot 可以提权并执行代码，从而攻陷开发者的机器。正如我所发现的，这是智能体系统中一种并不罕见的设计缺陷。

请继续留意这类设计缺陷，它们本应能在威胁建模阶段被轻松发现。
