# Anthropic 各团队如何使用 Claude Code

Anthropic 的内部团队正在借助 Claude Code 改变工作方式，使开发者和非技术人员都能处理复杂项目、自动完成任务，并弥补过去限制其生产力的技能鸿沟。

通过访谈我们自己的 Claude Code 重度用户，我们收集了不同部门如何使用 Claude Code、它对工作产生的影响，以及其他考虑引入该工具的组织的实用建议。

## Claude Code 用于数据基础设施

数据基础设施团队负责为公司各部门整理全部业务数据。他们用 Claude Code 自动处理日常数据工程任务、排查复杂的基础设施问题，并创建有文档记录的工作流，方便技术人员和非技术人员独立访问和操作数据。

### Claude Code 的主要使用场景

**用截图调试 Kubernetes**

当 Kubernetes 集群宕机、无法调度新 Pod 时，团队用 Claude Code 来诊断问题。他们把仪表盘截图交给 Claude Code，它便逐个菜单地引导他们操作 Google Cloud 的界面，直到发现一条警告，提示 Pod 的 IP 地址已耗尽。随后 Claude Code 给出准确的命令，用于创建新的 IP 地址池并加入集群，从而无需网络专家介入。

**为财务团队打造纯文本工作流**

团队向财务同事演示如何编写纯文本文件来描述自己的数据工作流，再将其载入 Claude Code，即可获得全自动执行。没有编程经验的员工也能描述诸如"查询这个仪表盘、获取信息、运行这些查询、生成 Excel 输出"之类的步骤，Claude Code 便会执行整个工作流，甚至会主动询问日期等必需的输入。

**帮助新员工熟悉代码库**

当有新的数据科学家加入团队时，他们会被引导使用 Claude Code 来浏览庞大的代码库。Claude Code 会读取他们的 Claude.md 文件（即文档），找出特定任务相关的文件，解释数据管道的依赖关系，并帮助新人理解哪些上游数据源汇入了仪表盘。这取代了传统的数据目录和数据可发现性工具。

**会话结束时的文档更新**

团队会要求 Claude Code 在每项任务结束时总结已完成的工作会话并提出改进建议。这形成了一个持续改进的闭环：Claude Code 根据实际使用情况帮助完善 Claude.md 文档和工作流说明，使后续迭代更加高效。

**跨多个实例的并行任务管理**

在处理耗时较长的数据任务时，他们会在不同代码仓库中为不同项目同时打开多个 Claude Code 实例。每个实例都保持完整的上下文，因此当他们在数小时或数天后切回来时，Claude Code 仍清楚记得他们刚才在做什么、进行到了哪一步，从而实现真正无上下文丢失的并行工作流管理。

## Claude Code 用于数据基础设施

### 团队影响

**无需专业技能即可解决基础设施问题**

利用 Claude Code 诊断问题并给出准确修复方案，解决了通常需要拉系统或网络团队成员才能处理的 Kubernetes 集群问题。

**加速上手**

新的数据分析师和团队成员能够快速理解复杂系统，无需大量指导就能做出实质贡献。

**强化支持工作流**

可以处理规模大得多的数据量，并识别出人工无法手动审阅的异常（例如监控 200 个仪表盘）。

**实现跨团队自助服务**

没有编程经验的财务团队如今也能独立执行复杂的数据工作流。

### 来自数据基础设施团队的核心建议

**编写详尽的 Claude.md 文件**

你在 Claude.md 文件中把工作流、工具和预期记录得越清楚，Claude Code 的表现就越好。当已有成熟模式可供参考时，这能让 Claude Code 在搭建新数据管道等常规任务上表现出色。

**处理敏感数据时用 MCP 服务器而非命令行界面（CLI）**

他们建议使用 MCP 服务器（模型上下文协议服务器）而不是 BigQuery 命令行界面（CLI），以便对 Claude Code 能访问的内容保持更好的安全控制，尤其是在处理需要记录日志或可能涉及隐私问题的敏感数据时。

**分享团队使用会话**

团队组织过成员互相演示各自 Claude Code 工作流的活动。这有助于传播最佳实践，也让大家看到自己可能未曾发觉的用法。

## Claude Code 用于产品开发

Claude Code 团队用自己的产品来构建 Claude Code 的更新，拓展产品的企业能力和智能体循环功能。

### Claude Code 的主要使用场景

**用自动接受模式快速原型开发**

工程师通过启用"自动接受模式"（shift+tab）来快速原型开发，并设置自主循环，让 Claude 编写代码、运行测试并持续迭代。他们把不熟悉的问题抽象地交给 Claude，让其自主工作，然后在完成 80% 时接手评审，再做最后的打磨。团队强调要从干净的 git 状态开始，并定期提交检查点，这样一旦 Claude 跑偏，就能轻松回退任何错误的改动。

**核心功能的同步编码**

对于涉及应用业务逻辑的关键功能，团队会与 Claude Code 同步协作，给出包含具体实现指令的详细提示词。他们实时监控过程，确保代码质量、符合风格指南和架构合理，同时让 Claude 处理重复性的编码工作。

**构建 Vim 模式**

他们最成功的异步项目之一是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管它并非优先事项），最终实现中约 70% 来自 Claude 的自主工作，只需几次迭代便告完成。

**测试生成与缺陷修复**

他们在实现功能后用 Claude Code 编写全面的测试，并处理拉取请求（PR）评审中发现的小缺陷。他们还利用 GitHub Actions 集成，让 Claude 自动回复拉取请求中的意见，例如格式问题或函数重命名。

**代码库探索**

在接触不熟悉的代码库（例如单体仓库或 API 一侧）时，团队用 Claude Code 快速理解系统运作方式。他们不再等 Slack 上的回复，而是直接向 Claude 询问解释和代码引用，从而在上下文切换上节省大量时间。

## Claude Code 用于产品开发

### 团队影响

**更快的功能实现**

成功实现了 Vim 模式等复杂功能，其中 70% 的代码由 Claude 自主编写。

**提升开发速度**

能够快速为功能做原型并迭代想法，而不会陷入实现细节。

**通过自动化测试提升代码质量**

Claude 生成全面的测试并处理日常缺陷修复，在减少人工投入的同时维持高标准。

**更好的代码库探索**

团队成员无需等待同事回复，就能快速理解单体仓库中不熟悉的部分。

### 来自 Claude Code 团队的核心建议

**创建自给自足的循环**

让 Claude 通过自动运行构建、测试和代码检查来验证自己的工作。这样它能更长时间地自主工作并发现自己的错误，当你要求 Claude 在写代码前先生成测试时尤其有效。

**培养任务分类的直觉**

学会区分适合异步处理的任务（外围功能、原型开发）与需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用"自动接受模式"处理，而核心功能则需要更密切的监督。

**形成清晰、详尽的提示词**

当多个组件名称或功能相似时，要在请求中写得极为具体。提示词越好、越详细，你就越能放心让 Claude 独立工作，而不会意外改动代码库中不相关的部分。

## Claude Code 用于安全工程

安全工程团队专注于保障软件开发生命周期、供应链安全和开发环境安全。他们大量使用 Claude Code 编写和调试代码。

### Claude Code 的主要使用场景

**复杂基础设施调试**

在处理故障事件时，他们把堆栈跟踪和文档输入 Claude Code，要求它追踪代码库中的控制流。这大幅缩短了生产问题的解决时间，让他们能在约 5 分钟内理解原本需要 10–15 分钟手动扫代码才能搞清的问题。

**Terraform 代码评审与分析**

对于需要安全审批的基础设施变更，他们把 Terraform 计划复制进 Claude Code，问一句"这会做什么？我会后悔吗？"。这形成了更紧密的反馈闭环，让安全团队能更快评审和批准基础设施变更，减少开发流程中的瓶颈。

**文档综合与运维手册**

他们让 Claude Code 读取多份文档来源，生成 Markdown 运维手册、排障指南和概览。他们把这些精炼后的文档作为调试真实问题的上下文，相比在整个知识库中搜索，形成了更高效的工作流。

**测试驱动开发工作流**

过去他们的模式是"设计文档 → 粗糙代码 → 重构 → 放弃测试"，如今他们改为向 Claude Code 索要伪代码，引导它走测试驱动开发，并定期介入在卡住时给予引导，从而得到更可靠、更易测试的代码。

**上下文切换与项目上手**

在为"dependant"这类现有项目（一个用于安全审批流程的 Web 应用）做贡献时，他们用 Claude Code 编写、评审并执行以 Markdown 书写、存放在代码库中的规格说明，从而在几天而非几周内就能做出实质贡献。

## Claude Code 用于推理

推理团队负责管理内存系统，该系统在 Claude 读取提示词并生成回复的过程中存储信息。团队成员，尤其是刚接触机器学习的成员，可以大量使用 Claude Code 来弥补知识差距、加快工作。

### Claude Code 的主要使用场景

**代码库理解与上手**

在接手复杂代码库时，团队非常依赖 Claude Code 快速理解架构。他们不再手动搜索 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒钟就能得到结果，无需再问同事或手动查找。

**覆盖边界情况的单元测试生成**

写完核心功能后，他们会请 Claude 编写全面的单元测试。Claude 会自动纳入容易遗漏的边界情况，把原本耗费大量脑力的工作在几分钟内完成，如同一个可供评审的编程助手。

**机器学习概念讲解**

团队成员没有机器学习背景，因此依赖 Claude 解释模型专有的函数和设置。原本需要在 Google 上搜索并阅读文档一小时的事情，现在只需 10–20 分钟，研究时间减少了 80%。

**跨语言代码翻译**

在用不同编程语言测试功能时，他们只需说明想测试什么，Claude 就会用所需语言（如 Rust）写出逻辑，无需仅仅为了测试而去学一门新语言。

**命令记忆与 Kubernetes 管理**

他们不必记住复杂的 Kubernetes 命令，而是向 Claude 询问正确语法，比如"如何获取所有 Pod 或部署状态"，就能得到基础设施工作所需的准确命令。

### 团队影响

**加快机器学习概念学习**

研究时间减少 80%——原本要花一小时 Google 搜索的事情，现在 10–20 分钟即可完成。

**从代码生成入手**

给 Claude 具体指令让它编写逻辑，再验证正确性。这有助于在用它处理更复杂任务前，先建立对其能力的信任。

## Claude Code 用于数据科学与可视化

数据科学与机器学习工程团队需要复杂精深的可视化工具来理解模型表现，但构建这类工具往往需要掌握不熟悉的语言和框架。Claude Code 让这些团队无需成为全栈开发者，也能构建出生产级质量的分析仪表盘。

### Claude Code 的主要使用场景

**构建 JavaScript/TypeScript 仪表盘应用**

尽管自称"只懂一点点 JavaScript 和 TypeScript"，团队仍用 Claude Code 构建了完整的 React 应用，用于可视化强化学习模型的表现和训练数据。他们放手让 Claude 从零编写完整应用，比如一个 5000 行的 TypeScript 应用，而无需自己理解代码。这一点至关重要，因为可视化应用所需上下文相对较少，也不要求理解整个单体仓库，从而能够快速原型出工具，在训练和评估过程中理解模型表现。

**处理重复性重构任务**

当遇到合并冲突，或碰到对编辑器宏而言过于复杂、对大规模开发又不够大的半复杂文件重构时，他们把 Claude Code 当作"老虎机"用：先提交当前状态，让 Claude 自主工作 30 分钟，要么接受结果，要么不行就重新开始。

**创建持久化的分析工具，而非一次性 notebook**

团队不再构建用完即弃的一次性 Jupyter notebook，而是让 Claude 构建可在未来多次模型评估中复用的常驻 React 仪表盘。这一点很重要，因为理解 Claude 的表现"对团队而言是最重要的事情之一"——他们需要弄清模型在训练和评估中的表现，而"这其实并不简单，单看一个数字上涨，简单工具获取不到多少信号"。

**零依赖的任务委派**

对于完全陌生的代码库或语言中的任务，他们把整个实现委派给 Claude Code，利用它从单体仓库收集上下文并自主执行任务的能力，自己不参与实际编码。这让他们能在专业领域之外保持生产力，而不必花时间去学新技术。

## Claude Code 用于 API

API 知识团队负责 PDF 支持、引用和网页搜索等功能，这些功能把额外知识带入 Claude 的上下文窗口。在庞大复杂的代码库中工作，意味着不断遇到陌生的代码片段，要花大量时间弄清某项任务该看哪些文件，并在改动前积累上下文。Claude Code 充当向导，帮助他们理解系统架构、找出相关文件并解释复杂交互，从而改善这一体验。

### Claude Code 的主要使用场景

**第一步的工作流规划**

团队把 Claude Code 当作任何任务的"第一站"，让它指出修复缺陷、开发功能或做分析时该查看哪些文件。这取代了以往先手动浏览代码库、收集上下文再开工的耗时流程。

**跨代码库独立调试**

团队如今有信心处理代码库中陌生部分的缺陷，而不必向他人求助。他们可以问 Claude："你觉得你能修这个 bug 吗？我看到的行为是这样的"，往往立刻就能取得进展——考虑到所需投入的时间，这在过去是做不到的。

**通过内部试用进行模型迭代测试**

Claude Code 会自动使用最新的研究模型快照，因此成为他们体验模型变化的主要方式。这让他们在开发周期中直接获得有关模型行为变化的反馈，而这是以往发布时所没有的。

**消除上下文切换开销**

他们不再需要复制代码片段、把文件拖进 Claude.ai 并大段解释问题，而是直接在 Claude Code 中提问，无需额外收集上下文，显著降低了心智负担。

## Claude Code 用于增长营销

增长营销团队专注于搭建效果营销渠道，覆盖付费搜索、付费社交、移动应用商店、邮件营销和搜索引擎优化（SEO）。作为一个只有一名成员的非技术团队，他们用 Claude Code 自动执行重复的营销任务，并创建传统上需要大量工程资源的智能体工作流。

### Claude Code 的主要使用场景

**自动生成 Google Ads 创意**

团队构建了一个智能体工作流，用于处理包含数百条现有广告及其效果指标的 CSV 文件，找出表现不佳的广告进行迭代，并生成符合严格字数限制的新版本（标题 30 字符，描述 90 字符）。借助两个专门的子智能体（一个负责标题，一个负责描述），系统能在几分钟内生成数百条新广告，而无需在多个广告系列中手动逐条制作。这让他们得以大规模测试和迭代，而这在过去要花大量时间才能做到。

**用于批量生成创意的 Figma 插件**

他们不再为付费社交广告手动复制和编辑静态图片，而是开发了一个 Figma 插件，可识别画框并以编程方式生成多达 100 个广告变体，只需替换标题和描述即可，把原本要花数小时复制粘贴的工作缩短到每批半秒。这使创意产出提升 10 倍，让团队能在关键社交渠道上测试多得多的创意变体。

**用于广告系列分析的 Meta Ads MCP 服务器**

他们创建了一个与 Meta Ads API 集成的 MCP 服务器（模型上下文协议服务器），可直接在 Claude Desktop 应用中查询广告系列表现、花费数据和广告效果，无需在不同平台间切换来分析效果，节省了大量关键时间——在这里，每一分效率提升都会转化为更好的投资回报率（ROI）。

**结合记忆系统的高级提示工程**

他们实现了一个简易的记忆系统，记录各轮广告迭代中的假设与实验，让系统在生成新变体时能把之前的测试结果拉入上下文，形成一个自我改进的测试框架。这使得系统化实验成为可能，而这在过去靠人工追踪是无法实现的。

### 来自增长营销团队的核心建议

**找出具备 API 的重复任务**

留意那些涉及重复操作、且所用工具带 API 的工作流（如广告平台、设计工具、分析平台）。这些是自动化的理想对象，也是 Claude Code 最能创造价值的地方。

不要试图用一个提示词或一套工作流包办一切，而应为特定任务创建独立的智能体（比如他们的标题智能体与描述智能体）。这在处理复杂需求时更易调试，也能提高输出质量。

先花大量时间在 Claude.ai 中想清楚整个工作流，再让 Claude.ai 生成一份全面的提示词和代码结构，供 Claude Code 参考。此外，要一步步推进，而不是要求一次性方案，以免 Claude 被复杂任务压垮。

## Claude Code 用于产品设计

产品设计团队为 Claude Code、Claude.ai 和 Anthropic API 提供支持，专注于构建 AI 产品。即便非开发者也能用 Claude Code 弥合设计与工程之间的传统鸿沟，直接实现自己的设计构想，无需与工程师反复来回沟通。

### Claude Code 的主要使用场景

**前端打磨与状态管理改动**

过去，为了让字体、颜色、间距等视觉细节得到调整，他们要写大量设计文档并与工程师反复沟通；如今他们直接用 Claude Code 实现这些改动。工程师注意到他们正在做"通常不会看到设计师做的大规模状态管理改动"，从而能够精准达成心中所想的质量。

**用 GitHub Actions 自动建单**

借助 Claude Code 的 GitHub 集成，他们只需提交描述所需改动的 issue／工单，Claude 就会自动提出代码方案，而无需打开 Claude Code，为长期积压的打磨任务打造了无缝的缺陷修复与功能完善工作流。

**快速交互式原型**

把模拟图粘贴进 Claude Code，他们就能生成功能完整、工程师可立即理解并迭代的原型，取代了传统上静态 Figma 设计需要大量解释、再转化为可运行代码的循环。

**边界情况发现与系统架构理解**

他们用 Claude Code 梳理错误状态、逻辑流程和不同的系统状态，从而在设计阶段就发现边界情况，而不是等到开发后期才发现，从根本上提升了初始设计的质量。

**复杂文案修改与合规**

对于在全代码库中移除"研究预览版"字样之类的任务，他们用 Claude Code 找出所有实例、审阅周边文案、与法务实时协调改动并落地更新——整个过程只需两次 30 分钟的电话会，而非一周的来回协调。

### 开发工作流影响

**实现试验式开发**

他们如今采用"尝试并回退"的方法，频繁提交检查点，以便测试 Claude 的自主实现尝试并在需要时回退，从而支持更富试验性的开发。

**加速文档工作**

Claude Code 会自动添加有用的注释，在文档工作上节省大量时间，不过他们指出它有时会在奇怪的位置加注释，或采用值得商榷的代码组织方式。

**有局限的提速**

尽管 Claude Code 能以"相对较少的时间"完成中小型拉取请求（PR），但他们承认，它大约只有三分之一的首次尝试就能成功，其余情况需要额外引导或人工介入。

### 来自强化学习工程团队的核心建议

**针对特定模式定制 Claude.md 文件**

在 Claude.md 文件中加入指令，防止 Claude 反复犯工具调用错误，例如告诉它"运行 pytest 而不是 run，不要随便 cd——直接用正确的路径"。这显著提升了稳定性。

**采用重检查点的工作流**

在 Claude 改动代码时定期提交，这样实验不成功时就能轻松回退。这支持一种无风险的、更富试验性的开发方式。

**先试一次性方案，再协作**

先给 Claude 一个简短提示词，让它尝试完整实现。如果成功（大约三分之一的情况），你就节省了大量时间；如果不成功，再切换到更偏协作、有引导的方式。

## Claude Code 用于法务

### 工作方式与影响

**在 Claude.ai 中规划，在 Claude Code 中构建**

他们采用两步流程：先用 Claude.ai 头脑风暴和规划，再转到 Claude Code 实现，并要求它放慢节奏、一步步来，而不是一次性输出所有内容。

**视觉优先的方式**

他们经常用截图向 Claude Code 展示想要的界面样子，然后基于视觉反馈迭代，而不是用文字描述功能。

**原型驱动创新**

他们强调要克服分享"傻乎乎"或"玩具级"原型的顾虑，因为这些演示能启发他人看到未曾想过的可能性。

### 安全与合规意识

**MCP 集成的担忧**

作为产品律师，他们立刻意识到深度 MCP 集成的安全隐患，并指出，随着 AI 工具接入更多敏感系统，保守的安全姿态将形成障碍。

**合规工具的优先级**

他们主张随着 AI 能力扩展尽快构建合规工具，认识到创新与风险管理之间的平衡。

### 来自法务部门的核心建议

**先在 Claude.ai 中充分规划**

在转向 Claude Code 之前，先用 Claude 的对话界面把整个想法想透彻。然后让 Claude 把所有内容总结成一份分步骤的提示词，供实现使用。

**渐进且可视化地工作**

让 Claude Code 放慢速度，一次实现一步，这样你就能复制粘贴而不至于手忙脚乱。大量使用截图来展示你想要的界面样子。

**即便不完美也要分享原型**

克服藏起"玩具"项目或未完成工作的冲动——分享原型能帮助他人看到可能性，并在平时少有交流的部门间激发创新。
