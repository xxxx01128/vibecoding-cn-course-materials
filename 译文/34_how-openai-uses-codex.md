2 OpenAI 如何使用 Codex

<!-- page 3 -->
引言
在 OpenAI，Codex 每天被众多技术团队使用，例如安全、产品工程、前端、API、基础设施和性能工程团队。团队正用它来加速各类工程任务，从理解复杂系统、重构大型代码库，到交付新功能，以及在紧迫期限内解决故障事件。
基于对 OpenAI 工程师的访谈和内部使用数据，我们整理了这些使用案例与最佳实践，用以展示 Codex 如何帮助团队更快推进工作、提升工作质量，并在大规模场景下管理复杂性。

使用案例 1
代码理解
当团队在新人上手、调试或排查故障事件时，Codex 能帮助他们快速熟悉代码库中不熟悉的部分。
他们经常用 Codex 定位某个功能的核心逻辑、梳理服务或模块之间的关系，并追踪数据在系统中的流动。它还有助于揭示架构模式，或找出那些否则需要大量手工工作才能补上的文档缺口。
在故障事件响应期间，Codex 通过展示组件之间的交互，或追踪失败状态如何跨系统传播，帮助工程师快速进入陌生的领域。

使用案例 2
重构与迁移
Codex 常被用来做跨多个文件或代码包的改动。例如，当工程师更新某个 API、改变某种模式的实现方式，或迁移到新的依赖项时，Codex 能让改动被一致地应用。
当同样的更新需要在几十个文件中完成，或当更新需要理解那些用正则表达式或查找替换难以捕捉的结构与依赖关系时，它尤其有用。
他们也用它来做代码清理，比如拆分过大的模块、用现代模式替换旧模式，或者为代码做好更利于测试的准备。

使用案例 3
性能优化
Codex 被用来识别并解决性能瓶颈。
在调优或可靠性工作中，工程师会提示 Codex 分析缓慢或占用大量内存的代码路径，例如低效的循环、冗余的操作或开销高昂的查询，并给出优化后的替代方案，往往会带来效率与可靠性上的显著提升。
Codex 也被用来支持代码健康，识别那些仍在活跃使用中、但有风险或已被弃用的模式。我们的团队依赖它来帮助减少长期技术债，并主动预防回归问题。

使用案例 4
提升测试覆盖率
Codex 帮助工程师更快地编写测试——尤其是在覆盖率薄弱或完全缺失的地方。
在修复 bug 或做重构时，工程师经常让 Codex 建议能覆盖边缘情况或可能失败路径的测试。对于新代码，它可以基于函数签名和周边逻辑生成单元测试或集成测试。
Codex 尤其擅长识别边界条件，比如空输入、最大长度，或那些不常见但有效的状态——这些往往是初始测试容易遗漏的。

使用案例 5
提升开发速度
Codex 通过加速开发周期的起点和终点，帮助团队更快推进。
在启动新功能时，工程师用它生成脚手架样板代码——创建文件夹、模块和 API 存根，无需手工拼接每一处，就能快速得到可运行的代码。
当项目临近发布时，Codex 通过处理那些较小但必不可少的任务来帮助团队赶上紧迫的截止日期，比如分流 bug、填补最后一公里的实现缺口，以及生成上线脚本、遥测钩子或配置文件。
它还被用来把产品反馈转化为起始代码。工程师经常粘贴一个用户请求或规格说明，让 Codex 生成一份粗略草稿，之后再回来完善。

使用案例 7
探索与构思
Codex 也适用于开放性的工作，比如寻找替代方案或验证设计决策。你可以让它给出解决问题的不同方式、探索不熟悉的模式，或对假设做压力测试。这有助于揭示权衡、扩展设计选项，并打磨实现选择。
它还被用来识别相关的 bug。给定一个已知问题或已弃用的方法，Codex 能在代码的其他地方找出相似的模式，让捕捉回归问题或完成清理工作变得更容易。

最佳实践
当 Codex 得到结构、上下文和迭代空间时，它能发挥最佳效果。以下是 OpenAI 团队正在培养的一些习惯，目的是在日常工作中持续从它身上获得价值。

从 Ask 模式开始
对于较大的改动，先用 Ask 模式让 Codex 给出一份实现计划，这份计划随后会成为你切换到 Code 模式时后续提示词的输入。这种两步流程能让 Codex 保持接地气，并有助于避免其输出中出现错误。Codex 最适合处理范围明确的任务，也就是你或同事大约一小时能完成、或需要几百行代码才能实现的任务。随着模型进步，预计它能承担的任务规模也会增大。

迭代改进 Codex 的开发环境
设置启动脚本、环境变量和互联网访问权限，能显著降低 Codex 的错误率。在运行任务时，留意那些可以在 Codex 环境配置中修正的构建错误。这可能需要几次迭代，但从长远来看能带来显著的效率提升。

像写 GitHub Issue 那样组织你的提示词
当提示词模仿你在 PR 或 issue 中描述改动的方式时，Codex 的响应更好。这意味着在相关时包含文件路径、组件名称、diff 和文档片段。用诸如「按照 [模块 X] 中的方式同样实现」这样的模式来提示，能改善结果。

把 Codex 任务队列当作轻量级待办列表
发起任务来记录那些旁支的想法、未完成的工作或顺手修的小问题。不必有压力要一次性产出一个完整的 PR。Codex 很适合作为一个暂存区，当你重新专注时可以回来看。

最佳实践
用 AGENTS.md 提供持久化的上下文
维护一个 AGENTS.md 文件，帮助 Codex 在跨提示词的过程中更高效地在你仓库里工作。这类文件通常包含命名约定、业务逻辑、已知的怪癖，或 Codex 无法仅从代码推断出的依赖关系。想了解更多如何组织 AGENTS.md 文件，请参阅文档。

利用「Best of N」提升输出质量
「Best of N」（多选一）功能让你可以为单个任务同时生成多个响应，从而快速探索多种解决方案并挑出最好的一个。对于更复杂的任务，你可以评审多个迭代版本，并把不同响应中的部分组合起来，得到更强的结果。

展望
Codex 仍处于研究预览阶段，但它已经在切实影响我们的构建方式，帮助我们更快推进、写出更好的代码，并承担那些原本永远不会被排上优先级的工作。
我们对未来的潜力感到兴奋——随着模型变得更好、Codex 更深地融入我们的工作流，我们期待解锁用它开发软件的更强大方式。我们会持续分享一路走来的所学所得。
